# HiveDesk 安装与升级

每台电脑运行本文件夹里的 Setup.exe。安装包包含所需运行组件，不需要安装开发工具。

## 第一次安装

1. 在要使用的每台电脑上安装，允许安装程序请求的管理员权限。
2. 打开 HiveDesk，设置设备名。同一 IPv4 局域网内自动发现，不需要 Key 或手动 IP。
3. 按 Ctrl + Alt + H 打开电脑列表，点击另一台电脑开始控制。
4. 按 Ctrl + Alt + 键盘左上角的反引号键返回本机。
5. 在本机按 Ctrl + Shift + Alt + 反引号键，踢掉正在控制本机的电脑。两端升级到 alpha.22 后，对方会返回自己的桌面并停止自动重连；再次手动选择才能重新控制。该固定热键只接受正常桌面的物理键盘，暂不覆盖锁屏/UAC 安全桌面。

默认登录后启动、显示托盘图标。双击托盘打开设置；隐藏托盘后，再次打开程序也能进入设置。
设置窗口固定大小，支持最小化。召唤快捷键可以在设置里修改。

## 升级

直接运行新版 Setup.exe 覆盖安装，不用先卸载。设备名、自启、托盘和快捷键设置会保留。
安装会短暂停止 HiveDesk，完成后重新启动。正常使用请分发安装包；解压文件版不负责安装被控端所需的系统服务。

首次请手动安装 alpha.34（已有 alpha.27 或更新版本可等待自动升级），设置标题应显示 **0.1.0-alpha.34**。此后系统服务会自动从 [GitHub Releases](https://github.com/jtheller/hivedesk/releases/latest) 获取新版：启动约 60–90 秒后首次检查，之后每 15 分钟检查一次。后台下载并验证发布签名、文件大小和 SHA256；没有更新或检查失败时继续正常使用。

alpha.34 修复 Windows 已将光标绘入采集画面时，观看端仍额外显示光标的问题。光标显示方式随对应视频帧传递，在该帧成功提交显示后切换，避免丢帧或显示忙碌时状态错配。需要两台都升级；与旧版连接时仍采用旧行为。双机拖窗叠影是否完全消失仍需实际复测。

alpha.32 在设置版本号旁新增 **Check for updates（检查更新）**。点击会立即检查签名发布并显示结果；有新版时唤醒自动更新，无需等下一轮定时检查。连接仍在使用时继续等待空闲，不会强制断开。检查失败或更新服务暂不可用时会明确提示，可稍后重试。

alpha.33 新增 **Prefer maximum GPU performance（GPU 最高性能优先）** 复选框，用于对比本机的 NVIDIA 电源策略。勾选只修改 HiveDesk 编码和观看进程的应用配置；取消恢复勾选前的设置，不修改全局驱动策略。它会立即保存，不需要再点 Save；请先保存其他表单修改。设置窗口随后关闭，等远控连接空闲后自动重启视频进程并重新打开设置，无需重启 Windows。正在控制、被控、连接中或重连的会话会阻止重启，请结束本轮连接后再比较。

建议先只在被控端切换，使用相同的拖窗或大转场场景比较，再单独测试观看端。该选项是性能偏好，不保证锁定 P0 或固定频率；开启后功耗可能增加。驱动不支持、写入失败或外部设置冲突时会明确提示，不会假装已生效。卸载前可取消勾选恢复原策略。

安装会等待本机没有控制、被控、连接中或等待重连的远控会话；局域网常驻发现连接不影响更新。准备安装时停止接收新会话，退出空闲的程序并静默覆盖安装，完成后以原来的普通用户身份恢复托盘。没有额外的确认窗口，不会自动重启 Windows。主动等待重连会持续阻止更新，按逃生键回到本机即可取消重连。异常情况下若设置窗口单独留在运行，更新也会等它关闭。

alpha.31 修正流水线吞吐估算，避免把单帧等待时间当成硬件帧率上限；新增编码完成时间，使慢编码不会被误判为网络积压并反复请求关键帧。诊断状态独立发送，不再阻塞采集线程。两台都升级后启用新的时间信息；与旧版连接仍兼容，但保留旧版帧新鲜度判断。主屏刷新率、原分辨率和 4:4:4 保持不变。

接收端将解码提交、GPU 色彩转换和显示调度分开，使用有界交接。显示端每次选择最新完成的画面，跳过已被替代的画面；已完成画面的显示延迟不会直接破坏有效的解码引用链。自动降速依据实际压缩帧积压，不把单帧解码等待时间当成硬件吞吐上限。

alpha.30 修复锁屏输入线程缺少桌面输入回放权限，以及锁屏/解锁后采集重启把视频序号归零的问题。请先确认被控电脑已更新，再手动复测“锁屏 → 上推封面 → 输入 PIN → 登录后继续操作”；也请检查远控保持连接时，在被控电脑本地登录后能否继续刷新画面。开发测试不会自动锁定你正在使用的电脑。输入错误码和采集恢复记录写入被控电脑的本地日志，不记录 PIN 或按键内容。

alpha.28 的 Debug 浮层按约 16ms UI tick 刷新，FPS 和码率使用 250ms 滚动窗口；两端都更新后才能获得快速来源端统计。黄色表示偏慢，红色表示超出预算或严重异常，灰色表示空闲或样本过旧。丢帧计数只在新增时短暂变色。底色半透明，文字保持清晰，鼠标可以穿透操作远端。磁盘诊断日志仍约每秒写入，不跟随每次绘制写盘。

alpha.26 起，Debug 浮层、异常角标和重连提示统一位于左上角，距离左边和顶部各 16 DIP，随系统缩放。

本版包含 alpha.25 的键鼠输入升级：独立捕获和发送线程、独立加密输入连接，以及被控端独立的系统输入管道，使输入不再等待侧栏绘制、剪贴板处理、视频传输或编码重启。请两台都覆盖安装，以使用完整的独立输入路径；连接旧版本仍可使用原有控制通道。

切换电脑时，原有文字剪贴板交接完成后才开启输入。之后的剪贴板同步与键鼠输入分别处理；实时复制与立即粘贴之间没有新增跨通道顺序保证。键鼠积压超过 100 ms 或队列溢出时，会结束异常输入会话并释放远端按键，避免恢复后补放过时操作。

本版保留 alpha.24 的动态画面修复、自动 CBR、4:4:4、原始分辨率、旧帧淘汰和两个固定逃生/踢人热键；帧率与码率继续自动管理。

目标帧率仍取两端主屏刷新率的较低值，不修改真实屏幕刷新率。网络不足时先调整码率，再按画质预算限制帧率；编码器使用 QP16–22、目标 QP18，避免简单画面消耗过多码率。画质保护仍属有损编码，不能保证任意内容完全无损或绝不出现压缩痕迹。静态桌面不会为了凑码率发送填充数据。

持续阻塞时，程序会丢弃过时画面，必要时重新连接；恢复期间可能短暂停顿。目标是回到新画面，避免把积压帧慢放或集中补播。真实效果请在动态画面下双向验证。

## 使用范围

Windows x64；两端需要支持 HEVC 4:4:4 的 NVIDIA 显卡，主屏连接到该显卡。
编码接口仍为 NVENC/NVDEC API 11.1，保留早期 R500 系列驱动兼容目标，不需要 CUDA 运行时；本轮没有重新验证旧驱动硬件。
仅用于可信局域网：同网段运行 HiveDesk 的设备可以互相控制，没有额外配对确认。
系统登录密码/PIN 保持原样；首次登录前的远程访问和 Ctrl + Alt + Del 生成尚未支持。

## 卸载与诊断

在 Windows 的“已安装的应用”中卸载 HiveDesk，安装的服务与防火墙规则会一并移除。
每个用户的设置和 log.txt 位于其 LOCALAPPDATA 下的 HiveDesk 文件夹；升级会保留它们。
SHA256SUMS.txt 提供本文件夹安装包的完整性校验值，不代表数字签名。

## 实时调试浮层

在设置里打开 **Debug overlay**，点 **Save**。控制另一台电脑时，左上角会显示目标/限速帧率、实际收帧/解码/呈现帧率、耗时、码率和限速原因；返回本机会隐藏。新安装默认关闭。
两端都升级到 alpha.14 后才有完整的源端编码、捕获等待和发送等待数据；旧版仍可连接，只显示可取得的数据。静止桌面发送帧数少是正常的，请在持续滚动或播放动态画面时观察。Present 是提交呈现的次数，不是屏幕实际扫描次数。
两端升级到 alpha.23 后，浮层与诊断文件还会显示自动 CBR 的目标/实际码率、平均 QP、调节原因，以及帧过期、序号断层和队列溢出次数。
alpha.24 还在各电脑本地的诊断 JSON 中细分加密、视频发送完成、排队和发送就绪间隔，以及接收端的映射等待、颜色转换、绘制和呈现间隔。排查双向卡顿时应同时保留两台的诊断文件；这些是处理阶段的时间，不等于屏幕实际显示延迟。大转场仍可能产生较大的压缩帧或更长的硬件处理时间，需要在真实使用中验证。

alpha.25 在浮层中增加两行输入数据：发送到注入完成确认返回的 **Input ACK roundtrip p50/p99**，以及发送前调度、被控端排队和注入阶段的耗时。本地诊断 JSON 还提供发送前耗时及 ACK 往返的 p50/p95/p99/max，队列数量、未确认数量和样本年龄。移动鼠标或打字后才会产生样本。

ACK 表示 Windows 已接受该次输入，或已经释放的按键无需重复释放；不代表应用已经处理或屏幕已经显示。往返数据包含被控端排队、输入桌面切换、SendInput 和返回网络耗时，不能当作单程延迟或除以二直接估算。这里没有测量物理 USB 轮询，也没有保证与本地 USB 完全相同。

开发回归使用不会触碰桌面的模拟注入器验证输入顺序、独立管道和释放行为。真实双机输入手感、锁屏桌面注入及长时间游戏/拖拽表现，需要两台更新后实测；开发验证没有安装、重启或替换正在运行的版本。
