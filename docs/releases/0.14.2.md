# 0.14.2

Fixes Intel live-rate adjustment found on JT after the 0.14.1 first-frame fix.
The generated production test reached its rate change but Reset returned
MFX_ERR_INVALID_VIDEO_PARAM (-15) after Query accepted the request.

Capture pacing now changes independently of the codec's fixed HEVC sequence
timing. Reference-preserving Reset only proposes bitrate changes; a pacing-only
change does not reset the encoder. Intel documents a limited set of parameters
that may change without starting a new sequence, which excludes frame rate:
https://intel.github.io/libvpl/latest/API_ref/VPL_structs_encode.html#_CPPv424mfxExtEncoderResetOption

If a runtime still rejects a bitrate reset as unsupported/invalid/incompatible,
the host verifies that its original format, quality, timing and rate remain
intact before disabling live resets for that session. Adaptive capture pacing
continues. Device failures and altered configuration remain errors. The real
generated-pipeline diagnostic checks subsequent picture order, decoded color,
requested recovery IDR and absence of unexpected IDRs after a declined change.

NVIDIA encoding, decoding and pacing implementations are unchanged.
