# 0.14.0

Adds an Intel primary-display HEVC 4:4:4 hardware host backend. Intel hosts
previously entered the NVIDIA-only encoder and could not produce desktop video.
Backend selection follows the primary display adapter; existing NVIDIA codec
implementation and receiving behavior are retained.

Intel uses GPU full-range BT.709 color conversion, bounded AYUV system-memory
surfaces for legacy Media SDK compatibility, two in-flight jobs and the existing
capture/output/network scheduling. It keeps original resolution, 8-bit 4:4:4,
no B frames and CBR with QP quality guardrails. Each recovery IDR is validated
against its actual SPS; frame timestamps must match submission order. Supported
live rate changes preserve the coded sequence; unsupported queries retain the
codec state and adaptive frame pacing. This first Intel path includes readback
and upload, and is not a zero-copy implementation.

The separately negotiated `host` remote diagnostic tests generated Intel
production encoding, decoded color, rate changes, forced IDR, bounded ownership
and draining, then the real primary capture path and recovery. It uses fixed
installed code, with no input, clipboard, saved frames or arbitrary remote
commands. Existing diagnostics remain compatible with older peers. The overlay
uses the vendor-neutral label "Codec latency"; telemetry wire fields are retained.

Qualification before integration: JT's Iris Plus Graphics (8086:8a52), driver
31.0.101.2130 / Media SDK 1.35 passed a 16-frame actual HEVC444 hardware encode
and decode test in 0.13.7. Production streaming and sustained-motion results must
be recorded separately; this is not a claim of support for every Intel GPU.
Intel and AMD receiving still use the existing software fallback when NVDEC is
unavailable. Intel hardware decoding and AMD hosting are not included.
