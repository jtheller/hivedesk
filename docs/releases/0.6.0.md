# 0.6.0

Copy and paste images, files and folders between HiveDesk computers. Both ends
need 0.6.0; older peers retain Unicode text clipboard handoff.

- Lossless PNG and native DIB/DIBV5 bitmap data, including supported alpha data.
- Explorer file selections, multiple files, nested folders and empty files/folders.
- Native OLE FileGroupDescriptorW/FileContents with seekable 64-bit IStream and
  asynchronous Shell extraction. Transfer file contents only when pasted; no
  eager upload or temporary-file staging. Cross-computer cut is treated as copy
  and never deletes the source.
- A separate authenticated AES-GCM clipboard connection carries bounded 256 KiB
  requests/replies. Video, input and control readers remain independent. A failed
  clipboard lane can repair without restarting the desktop connection.
- Dedicated clipboard STA, sequence-aware handoff, listener echo suppression,
  clipboard carry-back without proxy cycles and reconnect generation checks.
- File reads are restricted to advertised objects, validate size/identity/mtime,
  and reject stale sources and unsafe manifests. No content or paths in diagnostics.
- Active clipboard copy operations defer automatic update and GPU-policy restart.

Limits: images total at most 256 MiB per clipboard snapshot; text at most 1 MiB
UTF-16; at most 4096 file/folder entries, with each relative Shell filename under
260 UTF-16 characters. Junctions/symlinks are rejected. File contents are streamed
with 64-bit offsets, without a whole-file size cap below the signed 64-bit range.
The source computer and source files must remain available. File-manager selections
are supported; application-specific virtual attachments and rich text/HTML are not
part of this release.

Validation includes isolated native clipboard/OLE calls, the actual Windows folder
drop target copying generated nested files through an encrypted connection, exact
byte comparison, PNG/DIBV5, large offsets, seek/clone/EOF, stale/unauthorized reads,
reconnect and blocked-control/video/input independence. The normal full suite and
repeated session/UI/clipboard regressions remain release gates. No test writes the
user's interactive clipboard or injects input into the active desktop.
