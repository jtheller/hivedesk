# 0.16.3

Fixes the fullscreen viewer trapping the local pointer on one display when the
viewing computer has multiple monitors. Ordinary absolute mouse mode no longer
clips the cursor to the viewer. Relative mouse mode retains its deliberate
center capture, with the existing escape and Alt stats-positioning behavior.

Mouse motion and clicks outside the viewer stay local, including negative
monitor coordinates. A drag that starts on the local desktop stays local when
it crosses the viewer; a remote button released on another screen is released
remotely without a stray local click. Fullscreen input now observes foreground
focus just like windowed input, so local applications receive their typing.

Remote cursor synchronization cannot pull the pointer back from another local
monitor or an unfocused viewer. Cursor correction uses virtual-desktop
coordinates, and viewer input mapping respects the actual client origin.
Remote capture remains primary-monitor-only; no video pipeline changes.

Validation exercises all four screen edges, local/remote drags across the
boundary, unfocused keyboard routing, negative display origins, cursor-sync
suppression/resumption, and the existing Alt HUD drag and nested-control paths.
These regression cases run on isolated Windows test stations without driving
the user's desktop; physical multi-monitor UX remains a live acceptance check.
