# 0.3.2

- Floating viewers now have a normal Windows maximize button and support native
  maximize/restore, including the system menu and caption double-click. Maximized
  windows fill the work area; the video stays proportional with letterboxing.
  Restored-window resizing still follows the source aspect ratio. Source size
  changes while maximized update the future restored ratio without resizing the
  maximized window. Restore layout stays deferred outside DXGI size callbacks.
- Hotkey card entrances now finish within 300 ms. The first-to-last start delay
  increases from 60 to 120 ms, giving a more visible stagger while every card
  completes on the same deadline. The background fade remains 240 ms; mouse
  hot-corner behavior and the 140 ms drag displacement remain unchanged.
- Add a code-checked scope/status inventory in docs/STATUS.zh-CN.md, separating
  unfinished work, implemented behavior awaiting acceptance, and explicit scope
  exclusions. VPN/DEVR investigation remains paused.

Validation: native and WinUI release builds; 33 native checks, including native
maximize/restore, source resolution changes while maximized, aspect restoration,
waiting-cover alignment, and real asynchronous viewer create/decode/teardown on
an isolated window station. The explicit no-input generated-content DWM check
verifies visible card staggering, final pixels, insertion displacement and an
actual first video Present underneath a cover. No physical input probe is run.
