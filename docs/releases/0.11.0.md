# 0.11.0

Nested keyboard and mouse control now reaches the innermost HiveDesk viewer.
With A viewing B and B viewing C, input over B's active viewer is explicitly
forwarded to C before Windows injection. Keyboard presses, mouse buttons,
wheels and raw relative movement are not injected twice into B. Absolute
movement also positions B's cursor, with coordinates mapped through windowed
viewers and letterboxing. B's own UI, window chrome and secure desktop retain
local control.

Held keys and buttons retain their original destination. Dragging outside a
viewer still releases on that viewer; stale releases and held repeats cannot
be redirected into a replacement session. Parent disconnect/kick releases child
input without closing the intermediate computer's own viewer. An ordered ACK
ledger waits for both local cursor injection and downstream acceptance before
acknowledging upstream. It preserves the existing input credit/backpressure
mechanism rather than building an unbounded intermediate queue.

Authenticated, capability-negotiated input packets carry a bounded node path.
Events returning to a node already visited are consumed without injection or
further forwarding. This bounds A-B-A input loops, not nested connections.
Injected OS events remain excluded from physical input hooks. Automatic hot
corners remain owned by the physical pointer; remotely mirrored motion does
not open every intermediate switcher at once.

Upgrade every computer in the chain to 0.11.0 for nested control. Legacy input
wire format remains supported at older endpoints. Ctrl+Alt+physical backtick
still returns one level; Ctrl+Alt+Backspace still returns directly to the
physical local desktop without waiting for the network. Nested control here
is between HiveDesk instances, not third-party remote-control applications.

Validation includes held-edge and drag ownership, stale sessions/focus,
relative deltas, bounded loops and ACK ordering; encrypted transport route
serialization and malformed packets; actual Shell geometry on an invisible
station; and an actual App between two encrypted test peers. The App test
withholds the innermost ACK, checks all input kinds reach that peer without
duplicate local edges, checks loop consumption and parent-stop release, then
repeats the nested-return barrier tests. The final Windows injection sink is
mocked in that isolated fixture; real multi-machine UX is a separate acceptance
check. No synthetic input is sent to the user's working desktop.

All 48 native tests, managed Settings checks and real WinUI light/dark checks
passed. After the final route-release guard changes, the five affected relay,
prelogon, input-routing, Shell and App integration checks passed again. Prelogon
terminates repeated routes with an ordered broker ReleaseAll, so its cumulative
ACK cannot overtake earlier Windows injection.
