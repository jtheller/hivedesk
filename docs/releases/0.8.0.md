# 0.8.0

- Negotiate encrypted packetized UDP video between new peers. Small paced
  fragments, selective acknowledgements/retransmission and measured RTT replace
  whole-frame TCP write scheduling on the new lane. Control, input and clipboard
  remain independent reliable channels. Older peers retain TCP automatically.
- Preserve predictive reference ordering with per-IDR epochs and bounded
  reassembly. Rapid session changes cancel stale payload while retaining the
  congestion credit of packets already on the network. Late frames cannot
  reappear after a new epoch or TCP fallback.
- Bound UDP establishment to three seconds and stalled frame ownership to two
  seconds. Unavailable or stalled packet paths fall back to TCP with a fresh
  reference frame, preserving an independent stream in the reverse direction.
- Authenticate and encrypt every datagram with direction/connection-specific
  AES-GCM keys. Reject replay, invalid offsets, oversized allocations and wrong
  endpoints. Unique authenticated bytes feed existing automatic rate feedback.
- Add transport diagnostics and deterministic network/crypto/lifecycle tests.
  Native resolution, HEVC 4:4:4, QP guardrails and display refresh are unchanged.
- Fix feedback ownership: a late report from an obsolete viewing session no
  longer resets the active session's byte baseline and monotonically increasing
  report sequence, which could suppress automatic decoder-pressure adaptation.

No FEC is included: selective retransmission still costs a round trip when a
predictive fragment is missing. This release does not equate successful UDP
negotiation with a smooth remote desktop; real-peer first-picture, cadence and
stall measurements remain necessary.

Validation before packaging: 43/43 native checks, managed update/GPU-policy
checks and real WinUI light/dark checks passed. Hardware capture, color/quality,
encoder pipeline, generated motion, presentation, Peek, source freshness and
discovery checks passed. The automatic-pressure integration test exposed the
feedback-ownership bug above; after correction it reduced 59.94 Hz to 15 Hz and
recovered to 59.94 Hz, delivering all 269 encoded pictures. A separate hidden
HEVC 4:4:4 UDP loopback with 35 ms delayed feedback delivered all 369 pictures
with no sender rejection. These are integration checks using periodic IDRs,
not controlled motion-throughput or end-to-end input-latency benchmarks.
