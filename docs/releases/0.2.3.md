# 0.2.3

- Full-screen connection snapshots retain the source primary display's native
  pixel dimensions. JPEG quality is reduced to fit a 2 MiB packet budget; the
  sidebar uses separate small bitmaps. Older peers keep the 672x378 format.
  Both computers must update for native snapshots. Dimensions and memory remain
  bounded (8192 per edge, 32 Mi pixels, 128 MiB full-image cache).
- Summoning the switcher explicitly uploads its complete current-sized surface
  before committing its clips and fade. It no longer depends on a hidden-window
  repaint, and can recreate a failed composition device without a successful
  video connection.
- Desktop-service runtime failures are forwarded to the ordinary user log before
  restarting capture. Previously the original exception was only logged under
  SYSTEM, while the user log repeatedly reported capture resumed.
- `HiveDeskCheck --remote <IPv4>` provides a bounded 12-second video-start probe:
  version, snapshot, frame and source-diagnostic counts, with no desktop input,
  clipboard writes, visible viewer or saved images.

DEVR investigation: authenticated transport and snapshots work, but capture
restarts repeatedly on the same desktop without delivering video. This release
exposes the original failure; it does not claim to resolve that machine's capture
failure before its runtime exception is observed.

Regression checks cover native 1920x1200 JPEG detail, legacy fallback and bounds,
encrypted native snapshot packets larger than the old control limit, native
waiting-image selection, and repeated switcher reopening without any video frame.

Validation: 32/32 native CTest checks passed; native and WinUI release builds
completed successfully. Physical panel appearance still requires user confirmation.
