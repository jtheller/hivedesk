# 0.8.3

- Start a headless network endpoint before the first console logon, using the
  installed SYSTEM service and the existing desktop capture/input broker. Cache
  the last console user's public device identity and startup preference under
  protected machine settings. No user password or clipboard is cached there.
- Hand off the endpoint and broker permissions when the console's user identity
  changes. Ordinary lock/unlock keeps the existing broker and connections.
  Service recovery now checks every second and reacts to logoff/resume events.
  SCM also restarts a crashed service after bounded delays.
- Observe IPv4 address, interface and route notifications. Rebuild discovery
  listening/source sockets, announce every 250 ms for ten seconds, then return
  to the ordinary two-second interval. Poll addresses every five seconds as a
  fallback. Preserve healthy streams across notification bursts.
- Recover failed TCP/UDP listeners every 500 ms. Run connection attempts on a
  separate bounded discovery queue so an unreachable machine cannot stop LAN
  announcements or receiving other machines' announcements. Bind directed
  broadcasts to each actual local interface address.
- Let a rejected input-authority request retry after warm promotion instead of
  leaving the same session permanently pending. Keep prelogon control and live
  Peek sessions protected from OTA; the service, not the updater's user-tray
  launcher, owns SYSTEM endpoint restart.

Validation includes isolated real TCP/UDP bind conflicts and automatic recovery,
notification bursts preserving a paired connection, and an encrypted prelogon
protocol test with a fake desktop broker (warm/Peek/promotion, input refusal and
retry, independent ACK, stale cancellation, stop, identity and OTA policy).
The latter never injects physical input. A real reboot into the first Windows
sign-in screen remains a separate acceptance check; automated tests do not claim
to have performed a physical logoff, reboot, or PIN entry.

Completed validation: 44/44 native tests, managed update/GPU-policy checks and
real WinUI light/dark checks passed. Final transport/prelogon/path-probe checks
and isolated automatic rediscovery passed. A hidden HEVC 4:4:4 hardware loopback
with delayed feedback delivered 540/540 encoded frames with zero sender
rejections; this is not a two-computer latency or sustained-motion benchmark.
