# 0.9.0

Add automatic HEVC 4:4:4 CPU decoding for clients such as the GTX 1070, which can
encode this format but cannot decode it in NVDEC. Hardware initialization remains
preferred on NVIDIA; unsupported or unavailable hardware selects the software
backend before accepting video. Intel/AMD display adapters use the same software
backend without loading CUDA. Their hardware encode/decode integration is not
part of this release. Runtime corrupt/reference errors do not switch backends
mid-GOP.

The host bitstream, chroma resolution, input and network protocols are unchanged.
The receiver uses a pinned minimal LGPL FFmpeg 9.0.2 build with within-picture
threading, not frame-thread buffering. Full-resolution Y/U/V planes are uploaded
and converted with D3D11 using the existing full-range BT.709 matrix. Presentation
keeps the existing latest-ready ownership, display readiness, epoch, cursor,
warm/Peek and busy-Present behavior. No new settings switch is added.

Synchronous CPU service time feeds the existing automatic frame-rate controller.
It is separate from NVDEC mapping latency, which still does not cap throughput.
Only locally measured CPU decoding work is excluded from the 50 ms display
waiting budget; queued work, post-decode delay and the absolute one-second severe
backlog guard remain bounded. Sparse slow-CPU samples remain actionable and
expire during idle. Debug/JSON identify the selected decoder.

The DLLs are delay-loaded only for software decoding. Missing packaged libraries
produce an explicit error. Installers include the exact upstream source archive,
license and reproducible build scripts; build downloads are pinned by SHA256.

Validation:

- All 45 native CTest checks, managed settings/update/GPU-policy checks and real
  WinUI light/dark checks passed.
- CPU-only fixture: 24 exact-order HEVC pictures including P references,
  one-pixel chroma, resolution changes, IDR recovery and bad input rejection;
  no NVIDIA driver loaded.
- Both software and NVDEC passed real DWM Peek fade/reversal/promotion, 12
  replacement-preview lifecycles, 96 motion samples and 100 static checks with
  no pixel mismatch or repeated idle Present.
- NVDEC hidden desktop loopback passed authenticated video, delayed feedback
  and automatic-rate integration. A separate 20-second 2560x1440 software
  desktop session received 695 access units and observed 642 distinct presented
  pictures, with adaptive pressure feedback and no queue overflow. These are
  local integration checks, not a cross-machine smoothness benchmark.
- An isolated installation without codec DLLs reported the expected reinstall
  error with normal exit; the same executable still rendered through NVDEC.
- Software hidden loopback also passed using unmodified CPU feedback, with
  periodic IDR stress, continued presentation and no queue overflow. The existing
  injected 1 ms-capacity/near-60-FPS test is hardware-specific and fails under
  CPU overload; software mode intentionally tests real adaptive capacity instead
  of falsifying the decoder measurements. The NVDEC test retains its assertions.

GTX 1070/DEVR and physical Intel/AMD receiving-adapter acceptance remains pending.
Software decode performance depends on CPU, resolution and content; it preserves
4:4:4 rather than promising hardware-decoder frame rates. DEVR has a staged,
non-input diagnostic runner for separate reverse-direction acceptance.
