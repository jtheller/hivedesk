# 0.5.4

Fix Hive staying visible after the bottom-left taskbar trigger, including when
no remote viewer is open. The taskbar's temporary front position no longer
disables normal sidebar dismissal. Clicking outside or pressing Escape dismisses
Hive; a pointer-opened sidebar also fades away when leaving the panel. These
actions keep native taskbar/menu input local instead of lowering Explorer while
its click is still being processed.

Hit-test the actual window for taskbar clicks that overlap the sidebar rectangle.
Keep the native taskbar above Hive when reopening the sidebar, without raising it
above its menus. Returning to the viewer, choosing a device, explicitly toggling
Hive closed, returning locally or quitting still releases the temporary state.

Add an integrated regression on a noninteractive Windows window station, using
the real Shell, input dismissal policy, generation-checked owner messages, fade
completion and pointer timers. It covers local-only use, overlapping Start-button
coordinates, repeated reopening, drag/stale-route exclusions, hover dismissal and
viewer activation. The test reproduced both the swallowed dismissal and covered
Start button before their respective fixes.

Validation: all 39 native checks passed; the five affected checks were rerun after
the final window-order fix. The generated-content DWM crossfade check verifies
entry/exit pixels and unchanged foreground. These are automated regressions, not
an end-to-end physical click test of the user's real Explorer Start menu.
