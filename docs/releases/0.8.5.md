# 0.8.5

Retire the experimental **Steady display cadence** setting and its repeated-
presentation branch. The experiment's only exclusive behavior was redrawing
an already-presented image when no new picture was available; no demonstrated
benefit justifies making that behavior unconditional.

The normal presentation pipeline already waits for display availability, takes
the latest ready picture, and retries a busy Present without decoding again.
Keep those behaviors and the existing freshness, cursor and session fences.
After a successful Present, release picture ownership and wait for new work;
the swapchain retains the displayed pixels. No duplicate encoding or generated
motion frames are introduced. Capture, input and network policies are unchanged.

Remove the option from both WinUI and fallback settings, the preferences model,
and the viewer API. Remove legacy DisplayCadence keys during configuration load/
save so previously enabled installations also adopt the normal pipeline. Older
settings packets may carry the trailing boolean, but it is validated and ignored.
Local telemetry replaces the experiment-only repeated_presentations field with
presented_frames, a cumulative count of successful presentations.

Retain and adapt the generated-pixel regression checks: static pixels must stay
visible without additional Presents; motion must resume after idle, progress
monotonically without old/black frames, and retain its final image. Warm/Peek
activation and busy-Present recovery remain covered separately. Configuration
migration checks preserve unrelated preferences for old enabled/disabled values.

Validation: all 44 native checks, managed update/GPU-policy checks and real WinUI
light/dark self-tests passed. Generated normal-window pixels stayed unchanged
through 100 idle samples with zero extra Presents; 96 motion/idle samples reached
the final image monotonically. Four consecutive composition/Peek checks passed,
including 48 replacement-preview lifecycles. The first Peek run had a transparent-
background setup assertion failure before motion testing; adding pixel diagnostics
and repeating did not reproduce it. Its cause remains unconfirmed; no assertion
or product behavior was relaxed to obtain the passing runs.

The hidden 2560x1440 NVENC -> UDP -> NVDEC -> D3D11 integration delivered 520/520
frames with zero send backpressure; 35 ms delayed feedback retained a 59.94 fps
cap. This is a bounded local functional check, not a throughput benchmark or proof
of long-running two-machine smoothness. Capture, input and transport code were
not changed by this release.
