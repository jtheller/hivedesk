# 0.16.1

Refines the compact performance strip around the approved device-name and icon design.

- Full remote device name with original casing and Unicode spelling; normal
  names, values and icons share neutral white (#ECECEC). Bahnschrift is the
  Latin font; Windows font coverage and Uniscribe fallback handle other scripts.
- Four 16 DIP metric icons: offset stacked frames for FPS, a filled waveform
  for received bitrate, filled chip/card symbols for hardware encode/decode,
  and outline video/gear symbols for software encode/decode. Software encoding
  is represented for future backends; this release does not add an encoder.
- Presented FPS / negotiated target FPS, actual encoder backend (NVENC or QSV),
  decoder backend (NVDEC or FFmpeg), stage times and received Mbps. The existing
  source encode and decoder timings keep their original meaning; they are not
  GPU utilization or end-to-end latency. Unknown legacy encoders say Encoder.
- Unified 20 DIP group spacing, 6 DIP icon/text spacing and 12 DIP outside
  padding. The name separator uses the existing gap. The 28 DIP high strip
  sizes to content, reserves numeric widths to avoid routine update jitter,
  and constrains only the displayed name when a small viewer cannot fit it.
- Existing slow-stream hysteresis, inline warning colors, click-through behavior,
  stats shortcuts, detailed debug mode and delayed connection hints remain.
  Stats-off warnings still appear independently in the same corner.
- Encoder identity is an optional capability-gated diagnostic extension through
  the broker and network. Older peers keep their exact existing diagnostic wire
  layout. No video packets, codec setup, rate control, GPU scheduling, queues,
  input authority or desktop-transition behavior change.
- New default names use the physical DNS hostname instead of the NetBIOS alias.
  Saved/custom names are preserved: previously saved uppercase text is not
  guessed back into mixed case. Existing ANSI settings are atomically migrated
  to UTF-16 before writing Unicode names, preserving unrelated settings.

Validation includes native HUD rendering on light/dark backgrounds, multiple
DPIs, Unicode names and punctuation, transparency, freshness, stable widths,
legacy/new diagnostics negotiation and truncation, and settings migration.
Release packaging runs the complete native suite, managed bridge checks and
WinUI light/dark checks. Subjective live appearance remains user acceptance.

Implementation references: [Windows profile encoding behavior](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-writeprivateprofilestringw)
and [Uniscribe shaping/font fallback](https://learn.microsoft.com/en-us/windows/win32/api/usp10/nf-usp10-scriptstringanalyse).
