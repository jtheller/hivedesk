# 0.15.0

Adds explicit-selection wake support and active-session power ownership.

- Clicking a known on-link computer sends standard Wake-on-LAN packets to its
  authenticated, previously learned adapter MAC. Only the selected device is
  requested; retries are limited to ten attempts over thirty seconds and stop
  on connection, cancellation or selection of another computer. UDP submission
  is never treated as proof of waking or a successful desktop connection.
- Known wake targets remain selectable while offline for up to 24 hours after
  their last authenticated connection/update. This bounded cache is in memory
  and resets when HiveDesk restarts. Only on-link targets are offered; routing
  a magic packet to another network or a gateway is not attempted.
- New peers exchange the MAC of the adapter used by their authenticated control
  connection. Older peers can use an already-resolved local neighbor entry.
  The optional message is capability-gated and leaves the handshake unchanged.
- A formal desktop Start or warm-to-active promotion asks Windows to wake the
  display and holds system, execution and display power requests. Disconnect,
  cancellation, failed startup and process exit release those requests. Hive
  opening, snapshots, warm resources and Aero Peek do not acquire them.
- Resume notifications trigger the existing discovery/listener refresh and
  announcement burst even when the IP address has not changed.
- A fixed, read-only remote `power` diagnostic reports Modern Standby support,
  AC/battery state, supported sleep states, wake-armed and wake-programmable
  devices. It does not change drivers, power plans, RDP, BIOS or security policy.

Actual wake from Modern Standby/S3 depends on the computer, network adapter,
driver and Windows policy. Wi-Fi, USB network adapters and battery operation can
restrict wake; power requests cannot override explicit sleep or all OS limits.
This release does not prevent idle sleep permanently, disable Modern Standby,
or install a periodic wake timer. Successful code tests do not certify the
physical sleep/wake cycle on every device.

Codec, bitrate, frame pacing, video queues and input encoding are unchanged.
OTA continues to wait for active and reconnecting sessions to finish.
