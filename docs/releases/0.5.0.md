# 0.5.0

Separate viewer preparation and retirement from selection scheduling. New
selections can cancel obsolete preparation without waiting for its GPU teardown;
foreground preparation takes priority over queued background work. Each retired
viewer retains its own HWND lease, and an HWND cannot acquire another swapchain
until the previous preparation/retirement has completed.

Prewarming now retries failed viewers after a cooldown, checks the primary
adapter's WDDM memory budget before allocating another viewer, and serializes
background preparation. Warm recovery feedback runs every 250 ms independently
of the two-second lease renewal, so a cold-GPU first-frame expiry can request a
replacement promptly. A pending update retires warm-only work and prevents
renewal. Warm-only hosting no longer blocks idle OTA; actual viewing, hosting,
queued selection and reconnect intent still do.

Add a default-off **Steady display cadence (experimental)** checkbox. It retains
the most recently presented picture and redraws it at the DXGI display cadence
when no newer picture is ready. It does not encode duplicates, change physical
refresh rates, queue playback, or count duplicate presents as fresh-frame FPS.
Duplicate presentations have a separate diagnostic counter. This is an A/B
experiment, not a promise of additional real motion frames or proven smoothness.

High-latency input uses a bounded window derived from completed-injection ACKs:
the existing eight-packet window remains on fast links, while sustained measured
propagation may increase it up to 64. Host queue/injection pressure resets it to
eight; existing packets drain in order. There are no VPN, route or subnet
exceptions. This improves a code-level RTT bottleneck; DEVR continuous video
and end-to-end interaction remain unverified.

Begin AMD/Intel support with a separately packaged `HiveDeskMediaProbe.exe`,
official pinned VPL dispatcher and AMF headers, real adapter binding and hardware
capability queries. This is backend bring-up, not completed AMD/Intel streaming.
The NVIDIA agent/host have no new AMF/VPL dependencies and still use HEVC 4:4:4.
See `MEDIA-BACKENDS.md` for exact probe behavior and remaining integration.

Validation recorded during development:

- All 36 native CTest checks, including targeted input/transport/App lifecycle
  regressions, passed.
- Real-DWM generated warm-image aging/activation/presentation check; cadence
  repeats with no extra encoded frames and stops when disabled.
- Light/dark WinUI self-tests: settings persist, controls and Save fit the fixed
  window, existing update and GPU-policy behavior remains tested.
- The independent media probe enumerated DEVG's NVIDIA adapters without
  initializing a foreign codec backend. AMD/Intel hardware is not available here.

Live network switching and long-duration motion results are recorded separately;
isolated generated peers do not establish those results.
