# 0.8.4

- Adapt the UDP RTT baseline to persistent path changes. Add bounded RTO backoff
  so a jump above the previous timeout does not cause endless retransmission and
  prevent new RTT samples. Preserve congestion credit and short-term pressure.
- Automatically recover from TCP fallback on the same connection when both peers
  support it. Require repeated authenticated round-trip probes, an ordered TCP
  video barrier, acknowledgement of a new reference epoch, and a fresh UDP IDR.
  Failed handoffs return to TCP and progressively back off retries. Older peers
  retain their existing fallback behavior until updated.
- Separate sender and receiver expiration reasons. A blocked decoder/receive
  queue no longer falsely downgrades the reciprocal sender. Expose both counters
  and the recovering transport state in local diagnostics.
- Keep HEVC 4:4:4, native resolution, QP policy, independent input, refresh target,
  and GPU capture/decode/presentation tuning unchanged. Steady display cadence
  remains an optional client-side repeated-presentation experiment, off by default;
  it does not generate motion frames or change host encoding.

Regression checks cover transient/persistent/idle RTT changes, a simulated
2-to-140 ms path change, reply freshness and retry backoff, directional expiry,
blocked consumers during reverse traffic, recovery timeout and late barriers,
and real encrypted TCP-to-UDP restoration on the original connection. Simulation
and loopback results are not claims of physical scanout or end-to-end USB latency.

Validation passed 44/44 native tests, managed update/GPU-policy checks and WinUI
light/dark checks. The RTT-change simulation recovered to 298 delivered frames
in its final five seconds without frame expiry. Hidden HEVC 4:4:4 hardware
loopback with 35 ms delayed feedback delivered 540/540 frames, with zero sender
rejections, retransmissions or expirations and a final 59.940 Hz cap. Actual
multi-computer long-duration motion remains a separate acceptance measurement.
