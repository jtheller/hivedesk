# 0.7.10

- Return capture credit only when the actual overlapped video send budget has
  room. An empty unsent slot no longer admits speculative encoding behind full
  TCP writes. Completion returns credit promptly, outside transport locks.
- On an observed high-RTT path, a picture larger than the TCP byte window travels
  alone. Sustained blocked delivery temporarily reduces source GPU look-ahead
  to one picture; healthy operation restores the normal two-job pipeline.
  A delivery callback retains its source slot until downstream takes ownership.
- Record packet first-byte and authenticated completion times locally. Exclude
  this packet's intrinsic assembly time from playback-backlog age, while still
  rejecting pictures that waited behind earlier packets. Preserve the 50 ms
  local decoder/Present budget, sequence guards and session/epoch isolation.
- Bound progress-observed socket reads to 16 KiB. DEVR testing showed that a large outstanding receive could keep TCP bytes arriving while the application counter stayed unchanged for seconds; the bounded-read retest kept recovery alive during the slow packet.
- Recovery observes the exact receiving connection's byte counter directly,
  independent of UI activity. New video bytes can extend recovery; unchanged
  counters and control traffic cannot. Two seconds without progress still
  expires recovery, with a 30-second absolute ceiling for a trickling stream.

HEVC 4:4:4, native resolution and quality guardrails are unchanged. There are no
global network tweaks or topology-specific exceptions. This fixes application
backpressure and recovery behavior; it does not claim to repair DEVR's measured
TCP throughput/retransmission constraint or to provide high FPS on that path.
