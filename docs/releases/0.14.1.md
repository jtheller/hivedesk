# 0.14.1

Fixes Intel desktop startup on Media SDK 1.35. Real JT qualification of 0.14.0
returned MFX_ERR_MORE_DATA on the first EncodeFrameAsync call: codec AsyncDepth
2 buffered the first picture, so a static or warm desktop could not start.

The Intel codec now uses AsyncDepth 1, keeping the two application IO slots,
GPU color conversion, completion worker and independent delivery stage. The
first input must still yield a completion; no dummy frames or hidden playback
queue are introduced. GopRefDist and NumRefFrame remain 1. This follows Intel's
low-latency configuration guidance:
https://www.intel.cn/content/www/cn/zh/developer/articles/technical/video-conferencing-features-of-intel-media-software-development-kit.html

The existing generated production-pipeline and initial/recovery desktop tests
remain strict and caught the real first-picture failure. Capability-probe text
now points to the production host diagnostic, distinguishing codec qualification
from desktop validation. NVIDIA's encoder/decoder implementation is unchanged.
