# 0.13.4

File clipboard capture skips source entries that were deleted or became
inaccessible, instead of discarding the entire clipboard. Remaining files,
text and image formats are retained. Directory enumeration errors are confined
to the affected traversal so other selected roots can still be captured.
Only a skipped-entry count is logged, not file names or contents.

When a source disappears after it has already been advertised, lazy reads
return an item-scoped file-not-found result to Windows. Changed identities
return a reverted-source result; access failures remain errors. Optional failure
details preserve the existing wire failure flag for older peers. Other streams
and subsequent clipboard offers continue on the same connection. Deleted empty
files are validated too, rather than silently becoming successful empty copies.

Windows may still ask the user to skip a file deleted during paste; this release
does not report missing data as a successful copy or cache deleted file contents.
Descriptors keep stable indices for in-progress consumers. Clipboard scope
remains one hop and capture/video/input policies are unchanged.

Validation uses an isolated Windows clipboard and encrypted loopback peers:
delete after copy, same-offer surviving stream, missing empty file, subsequent
text, actual Shell file paste, DIB/PNG paste, all-missing capture, mixed text/image
retention, changed-source rejection, and existing input/video independence.
