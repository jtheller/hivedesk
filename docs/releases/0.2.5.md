# 0.2.5

- Video sends now time out after two seconds without new TCP payload progress,
  rather than two seconds for a complete encrypted frame. DEVR was receiving
  roughly 64 KiB after one second and 157 KiB after two seconds, but its sender
  closed the connection before the first frame could finish. Slow transfers
  can now complete; retransmission-only activity does not extend the deadline.
- TCP sampling begins only when a write remains pending for 500 ms. Ordinary
  LAN sends add no socket-statistics queries. The two in-flight video packets,
  one unsent frame, 50 ms unsent expiry, authentication and cancellation rules
  remain intact. Unsupported socket-statistics queries retain the bounded
  timeout fallback.
- The first-present wait renews its eight-second inactivity allowance as video
  bytes arrive. Escape and selection changes still cancel immediately; a
  replacement connection cannot inherit the old connection's progress.
- Startup diagnostics can isolate `--snapshot-only` and `--video-only`, and
  report each channel's TCP byte counts, windows, RTT and retransmissions.
  Video probes run for 30 seconds; snapshot-only probes run for 12 seconds.
  These probes do not inject input, write clipboard data or save images.

Regression coverage includes a throttled, authenticated 4 MiB overlapped video
packet taking longer than two seconds, a stopped reader, retransmission-only
counter changes, socket-statistics fallback and the existing queue/cancel tests.

Validation: native and WinUI release builds succeeded; 32/32 native CTest checks
passed. DEVR returned a native 2560x1440 snapshot on 0.2.4. Its video send-progress
fix requires 0.2.5 on the sender and subsequent live verification.
