# 0.7.0

Hover a remote computer in Hive to see its desktop without taking control.
Both endpoints need 0.7.0 for live Peek; older endpoints retain normal selection
and prewarming.

- Visible computers still prewarm on opening Hive. Only the hovered computer
  resumes continuous video; leaving pauses it while keeping the warm resources.
- Peek is a session-scoped warm operation. It cannot start a new host, displace
  an existing controller, enable input, or apply a clipboard handoff.
- The preview fades through DirectComposition without taking foreground focus.
  Its first frame must be presented before reveal. Hover changes invalidate
  queued completions, and pause requests do not wait for another session startup.
- Clicking a visible fullscreen preview reuses its HWND, decoder and host lease;
  it does not flash a snapshot over the live image. Dragging still opens the
  existing resizable, aspect-constrained viewer.
- Fix a dark flash during fast switching: prepare and commit the complete target
  snapshot before exposing the new window or hiding the previous one. Remove
  the snapshot's fade from a near-black background. Fade the cover out only after
  a newly presented post-selection frame and input readiness, including when a
  previously presented preview has been resized.

Validation covers generated live video under real DWM composition (pixel samples
for transparent readiness, fade-in/out and same-surface promotion), isolated full
App hover/switch/drag cancellation, stale UI completions, clipboard/input ordering,
and separate read-only installed-broker/network preview diagnostics.

The earlier NVIDIA driver-reset report is distinct from the transition defect;
this release does not claim that its underlying GPU fault has been resolved.
