# 0.8.1

- Preserve each frame's actual fragment-completion time while waiting for an
  earlier predictive reference. Catch-up cannot relabel an old picture as newly
  received or hide its local residence from presentation freshness checks.
- Feed completed UDP frames according to the active/warm viewer's compressed
  queue credit. A repaired gap can no longer dump a burst into the four-frame
  decode queue. Packet receive, ACKs and sending continue independently; the
  decoder does not hold the transport mutex or wait for display presentation.
- Include completed frames waiting for decoder credit in the same 32 MiB,
  128-frame receive ownership budget. Expired references invalidate the chain;
  bounded repeat reset requests recover even if a reset packet is lost. A new
  IDR epoch supersedes queued old pictures, and TCP fallback releases the old
  UDP receive queue.
- Apply receive credit to active sessions, prewarmed/Peek viewers and the
  read-only video diagnostic. The HEVC format, QP policy and wire capability are
  unchanged; 0.8.0 peers remain compatible.

0.8.0 assets are immutable. This patch follows the transport release with
stricter receive timing/ownership; it is not a replacement binary under that tag.

Validation: 43/43 native checks, managed update/GPU-policy checks and real WinUI
light/dark checks passed. The real encrypted socket test retains ten completed
frames behind consumer credit while continuing authenticated progress/ACKs,
then delivers them after credit returns. Timing tests preserve an early-complete
P-frame's timestamp while its earlier reference is repaired. Expired retained
references cannot release dependent pictures. Hidden HEVC 4:4:4 integrations
delivered 367/367 pictures through overload/recovery and 536/536 with delayed
feedback, with zero sender rejections. Generated presentation had 0/100 cadence
pixel mismatches. No physical-screen refresh or desktop input was changed.
