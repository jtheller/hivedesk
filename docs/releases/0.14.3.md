# 0.14.3

Isolates the Intel hardware encoder's D3D11 device from desktop capture on the
same primary adapter. The existing system-memory AYUV handoff is retained;
there is no new frame queue, texture-sharing operation or chroma conversion.

On JT, real desktop telemetry showed large codec-completion latency while
color conversion and receiving were inexpensive. Generated encoding without
DXGI capture did not show the same behavior. Previously the runtime used the
capture device, allowing blocking DXGI acquisition and asynchronous codec
workers to contend over a device/context. Device isolation removes that shared
ownership; its actual latency benefit must be measured on the real machine.

The hardware qualification test additionally requires a submitted picture to
complete while the capture-context multithread lock is held. Existing color,
frame order, forced IDR, rate-reset fallback and drain checks remain intact.
It also generates twelve frames at the actual primary resolution and reports
color/codec timing separately, avoiding a small-image versus full-desktop
comparison. This idle-only diagnostic does not display the generated content.

NVIDIA code paths, pacing, input and network behavior are unchanged. Active
sessions still defer OTA; this update does not force a streaming connection
to disconnect.
