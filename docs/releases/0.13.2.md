# 0.13.2

Periodic nested-input cleanup no longer blocks the UI/video-feedback timer on
the selection mutex or relay ACK ledger. If either is busy, periodic cleanup
retries on the next tick; input and stop callbacks retain ordered cleanup.
An isolated actual-App regression held each mutex and verified that encrypted
video feedback still arrived at the peer before the mutex was released. The
selection-lock test failed against the previous implementation.

Cumulative downstream input ACKs remain cumulative when forwarded upstream.
One completion no longer expands into a burst of acknowledgements and stale
per-event RTT samples. The final event's sequence, capture clock and timing
are retained; failed injection boundaries cannot be hidden by a later release.
Tests cover credit recovery at simulated 200 ms RTT and the actual encrypted
three-node App relay, alongside existing nested return/summon/cycle tests.

This includes 0.13.1's independent default-on lightweight diagnostic logging,
quiet idle behavior and the "Reduced frame rate" warning label. The previously
built 0.13.1 was not published because the required GitHub login was unavailable.
Release publishing now explicitly selects the repository's jtheller account
for authentication and pushes, without changing the global Git account.

Capture, codec, video queue, automatic rate and presentation policies are
unchanged. These tests demonstrate the scheduling fix and ACK behavior, not
a measured improvement on DEVR; real-machine motion acceptance remains pending.
