# 0.13.6

Intel qualification now supports Media SDK 1.x hardware sessions. The old test
rejected such sessions before encoding because it required VPL 2.x managed
surfaces, even when the driver reported exact HEVC 4:4:4 encode/decode support.
Older runtimes use bounded application-owned AYUV system-memory surfaces; the
hardware runtime performs upload/readback. Locked surfaces are not reused and
storage outlives codec shutdown, including asynchronous failures. VPL 2.x keeps
the existing managed D3D11 path. The test still checks the actual encoded SPS,
decoded chroma pattern, frame count and absence of reordering.

Capability probes report physical display dimensions without DPI virtualization.
Remote receive reports now include decode, conversion, drawing, presentation and
queue timings, so CPU codec pressure can be distinguished from rendering costs.

These are diagnostic changes. Intel production hosting and hardware receiving
remain pending integration; the existing NVIDIA pipeline is unchanged.

Generated regression coverage checks AYUV byte order, padded allocation, locked
surface ownership/reuse, memory bounds and rejection of format downgrades.
