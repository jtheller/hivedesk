# 0.13.5

Adds an explicit remote media diagnostic over the existing authenticated control
connection, so hardware qualification does not require SMB, SSH, RDP or manually
copying logs. The developer tool HiveDeskRemoteMediaProbe accepts capabilities,
intel-roundtrip, or receive. Both peers must advertise the new capability.

The agent runs only the installed fixed probes, as its current desktop user.
There is no remote shell, arbitrary executable, command argument, file retrieval,
keyboard injection or clipboard access. Receive requests a 15-second read-only
preview of the requesting computer; it cannot replace an active controller there.

One job at a time, a 30-second admission cooldown, bounded output and process
timeouts contain diagnostic work. Active local viewing, hosting, Peek, graphics
preparation, shutdown, update or requester disconnection prevent/cancel the job.
Child processes are contained in a kill-on-close job and do not inherit unrelated
application handles. Old peers retain their existing connection behavior.

The capability report includes driver versions and attached display dimensions.
Intel encoding remains a qualification probe, not a production host backend.
Intel/AMD receiving continues to use the existing HEVC 4:4:4 software decoder.
This release does not change NVIDIA encode/decode scheduling or stream quality.

Regression coverage exercises encrypted diagnostic request/reply, invalid modes,
unsupported feature negotiation, malformed/oversized payloads, process output
bounds, timeout/cancellation and active-desktop rejection. Actual Intel hardware
qualification is separate from these generated tests.
