Fix duplicate cursors when Windows has already drawn the pointer into the
captured desktop, a possible cause of cursor ghosting while dragging windows.

- Bind cursor composition to each captured image and encoding job, then carry
  it through the broker, network and decoder. The viewer suppresses its extra
  cursor only after that image is successfully submitted for presentation.
- Ownership-only capture changes refresh the image. Cached recovery frames,
  dropped/replaced pictures, busy/occluded presentation and reconnects preserve
  the correct image-associated state. Independent cursor motion remains fast.
- Update both endpoints for this fix. Connections to older versions preserve
  their previous frame format and cursor behavior.

Validation: 28/28 native checks, real GPU encoder-slot and hidden rendering
checks, managed bridge tests and private-desktop WinUI light/dark checks passed.
No live desktop input was injected. VI/DEVG drag behavior still needs an actual
two-computer comparison; this release does not claim physical scanout timing
or confirmed elimination of every source of cursor trails.
