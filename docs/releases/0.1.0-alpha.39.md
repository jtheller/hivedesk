# 0.1.0-alpha.39

Switching computers and reconnecting now displays the selected computer's real
desktop snapshot instead of leaving the previous viewer image on screen.

- Selection immediately covers the old viewer, then fades the target snapshot
  in over an opaque neutral background. Without a cached snapshot, the background
  and target name remain visible until that computer's snapshot arrives.
- The waiting badge identifies the computer and marks snapshots as snapshots.
  Input stays disabled while connecting; Ctrl+Alt+` cancels as before.
- The waiting layer fades out only after the new session has successfully
  submitted its first image with Present and its input channel is ready.
  This is a presentation-submission gate, not a physical-scanout measurement.
- Both fades use DirectComposition, with no slide or per-frame bitmap uploads;
  Windows' disabled-animation preference is respected.
- Snapshot requests and reply decoding no longer sit behind the command worker's
  first-frame wait. Late snapshots update only the matching computer's cache.
- Viewer readback no longer populates snapshots, preventing a waiting layer or
  old swap-chain content from being cached as another computer's desktop.

Validation: 32/32 native checks passed. The new shell regression runs in a child
process on a noninteractive window station, covering cached/missing snapshots,
late replies, wrong-peer completion, rapid switching during fade-out, first-frame
handoff, reconnection and cancellation. The real codec/async-render check verifies
the first-Present gate can complete without revealing a hidden viewer, and that
closing invalidates it. No input was injected into the user's desktop; physical
display animation quality and real network switching still need user observation.
