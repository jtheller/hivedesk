# 0.9.1

Fix delayed host cursor positions pulling the viewer pointer back after connection
or rapid reselection. An initial host cursor snapshot now establishes a baseline
and updates shape/visibility without moving the viewer's pointer.

Position updates carry a negotiated session identity and the viewer input capture
timestamp already acknowledged when the host physically moved its pointer. That
watermark is frozen at capture, not refreshed when a later shape packet is sent.
The viewer rejects old sessions, backward/repeated revisions and positions that
precede even queued/coalesced local mouse input. Rejected positions cannot be
replayed by later shape updates. Queued UI callbacks also retain the selection
generation. Relative mode continues to ignore absolute position corrections.
Host positions outside the primary display are ignored rather than clamped to
its edge or corner.

During mixed-version OTA, native cursor shape and visibility remain available,
while unscoped position correction is disabled. Both ends need 0.9.1 for causal
host-position synchronization. Input delivery, video codecs and frame scheduling
are unchanged. The first eight nonduplicate position decisions per viewer are
logged for bounded diagnosis (decision 0=current, 1=baseline, 2=session,
3=revision, 4=newer local input or revoked authority); a current candidate may still be blocked by the
existing local-motion/UI protections.

Validation: all 46 native CTest checks, managed settings/update/GPU-policy checks
and real WinUI light/dark checks passed. The final primary-bounds and escape
authority changes also passed targeted cursor, actual-hook, isolated Shell and
shell-video regressions. Tests cover malformed/scoped/legacy wire packets,
initial corner snapshots, delayed positions after local input, immutable host
input watermarks, same-peer reconnects, queued old UI callbacks, monotonic
revisions, cursor shape/visibility, relative mode and injected-event exclusion.
No physical input is injected into the user's active desktop during validation.
The specific intermittent DEVR symptom still needs real-use confirmation after
both endpoints update; these fixes address confirmed code-level races, not a
claim that a recorded real-device drift has been replayed end to end.
