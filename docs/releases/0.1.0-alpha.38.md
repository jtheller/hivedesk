# 0.1.0-alpha.38

Video sending now keeps up to two encrypted packets in overlapped Winsock I/O.
Previously it waited for each send completion before submitting the next packet,
which could stall the producer despite using an asynchronous API.

- The window contains at most two owned writes and one unsent frame. The unsent
  frame still expires after 50 ms and recovers with an IDR. Writes still have a
  150 ms deadline; failures abort the connection instead of replaying old motion.
- Each write owns its ciphertext, tag, event and OVERLAPPED storage until
  completion, including cancellation. A single writer preserves packet order.
- Local video_send diagnostics now include inflight (0–2). Send wait in the HUD
  remains producer waiting time in ms/s, not a frame's wire latency.
- Connection failures identify the control/video/input channel, address and
  whether TCP connection or handshake failed. Discovery keeps this detail.

Validation: 31/31 native checks passed, including an encrypted 32-packet ordering
test and a blocked receiver test proving two 16 MiB writes can be outstanding,
a third frame remains unsent, both writes cancel and no stale frame replays.
These tests do not establish physical-network motion smoothness or prove that
delayed TCP acknowledgements caused the observed stalls; that needs two-PC use.

VPN audit: automatic discovery/handshake accepts on-link IPv4 subnets, not
arbitrary routed addresses. Installer firewall rules allow UDP 47979 and TCP
47980 on Private/Domain profiles with LocalSubnet scope. Input still has a
100 ms completion deadline and eight outstanding credits. A measured 139 ms
round trip to DEVR exceeds that input budget. This release does not change VPN
trust boundaries or input deadlines, and does not claim to fix DEVR's missing
first frame without its capture/encoding logs.
